# Telegram-чат через GREEN-API

Frontend на React, TypeScript и Vite. Цель: подключить свой инстанс GREEN-API, создать личный чат по номеру телефона и обмениваться текстовыми сообщениями в Telegram.

## Текущее состояние

Выполнены все этапы 1–7: FSD-каркас, тестовая инфраструктура, адаптивный интерфейс, подключение Telegram-инстанса, создание чата по номеру, отправка текста, получение уведомлений и сквозная проверка через GREEN-API. Форма проверяет состояние и настройки инстанса перед открытием рабочего экрана. На стартовом экране также доступен просмотр через «Открыть демо чата».

В демо можно искать и переключать диалоги, создавать локальный чат по номеру и добавлять текстовые сообщения. Черновики независимы для каждого чата. Enter добавляет сообщение, Shift+Enter — перенос строки. Все данные вымышленные и сбрасываются при выходе или перезагрузке; сообщения в Telegram не отправляются. Поля подключения не содержат заранее сохранённых ключей.

## Запуск

Требуется Node.js 22.12+ и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Разработка с горячим обновлением |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run preview` | Просмотр предварительно собранного приложения |
| `npm run lint` | Проверка ESLint |
| `npm test` | Однократный запуск Vitest |
| `npm run test:watch` | Тесты в режиме наблюдения |

## Архитектура

Входная точка — `src/main.tsx`. Импорты `@/` указывают на `src/`.

| Слой | Ответственность |
| --- | --- |
| `app` | Инициализация, провайдеры, Redux store, глобальные стили |
| `pages` | Экран подключения и композиция мессенджера |
| `widgets` | Список чатов и область переписки |
| `features` | Формы подключения, создания чата и ввода сообщения |
| `entities` | Сессия, типы чата и сообщения, строка диалога и пузырь сообщения |
| `shared` | UI-примитивы, форматирование дат, тестовая инфраструктура |

Импортировать можно нижележащие слои через публичные экспорты слайсов. Слайсы одного слоя не импортируют друг друга. Внутри слайса используются относительные импорты. Не импортируйте store или app-level hooks из нижних слоёв: селекторы должны иметь узкие типы состояния.

Redux хранит только публичное состояние сессии; поля форм, чаты текущего сеанса и модальные окна — локальное состояние React. Временные демо-данные изолированы в модели страницы мессенджера. Токен хранится отдельно от Redux в памяти API-клиента и очищается при выходе или перезагрузке. Стили компонентов — `*.module.css`, общие переменные — в `app/styles/global.css`.

## Подключение GREEN-API

Введите `idInstance` и `apiTokenInstance` из личного кабинета. API URL зафиксирован как `https://4100.api.green-api.com`. Приложение проверяет `GetStateInstance` вместе с `GetSettings`. Инстанс должен быть авторизован, иметь тип `telegram`, пустой `webhookUrl` и включённые `incomingWebhook`, `outgoingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook`, `stateWebhook`. Учётные данные не записываются в Redux, исходники или постоянное хранилище.

После подключения приложение выполняет long polling через `ReceiveNotification`. Статусы `outgoingMessageStatus` обновляют исходящее сообщение до «Доставлено», «Прочитано» или ошибки. Текстовые входящие создают чат по номеру отправителя и появляются в переписке. Уведомления активного чата подтверждаются сразу; для другого чата `DeleteNotification` вызывается после его открытия. Пока такое уведомление не подтверждено, очередь GREEN-API не выдаёт следующее событие.

## Форматирование CSS

Все CSS-файлы, включая CSS Modules, оформляются многострочно: открывающая скобка на строке селектора, каждое свойство на отдельной строке с отступом в два пробела, закрывающая скобка на отдельной строке. Между правилами оставляйте пустую строку. Селекторы, разделённые запятыми, располагайте каждый на отдельной строке. Внутри медиазапросов и `@keyframes` используйте тот же формат с дополнительным отступом в два пробела на уровень вложенности. Однострочные блоки запрещены.

```css
.class {
  display: flex;
}

.nextClass {
  padding: 16px;
}
```

## Тестирование

Тесты `*.test.ts(x)` располагаются рядом с проверяемым модулем. Vitest использует jsdom, Testing Library и jest-dom. MSW настроен для перехвата запросов: каждый тест добавляет обработчики через `server.use(...)`; необработанные запросы считаются ошибкой. Реальные ключи и отправка сообщений для автоматических тестов не нужны.

## Статус проверки

Реальный обмен проверен на авторизованном Telegram-инстансе GREEN-API: сообщения отправляются из приложения, а ответы получателя появляются в соответствующем чате.

Приложение использует один потребитель очереди на инстанс и хранит данные только в памяти сеанса. После перезагрузки локальная переписка исчезает, подтверждённые уведомления повторно не загружаются. Прямой доступ из браузера и CORS проверены на этапе подключения.
